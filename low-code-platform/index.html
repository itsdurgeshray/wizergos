FAQ

Questions about building with Wizergos

What can we build with Wizergos?

You can configure business applications with forms, data, rules, integrations, reporting, and conversational experiences. Common implementation patterns include service requests, onboarding, document workflows, and operational tools.

Can Wizergos connect to our existing systems?

Wizergos provides configurable REST, SOAP, and ODBC connections, along with selected messaging and business-service integrations. Your implementation determines which connections, credentials, and data mappings are required.

How does AI fit into the platform?

AI can support document-aware experiences, conversational interfaces, and agents that use saved automations as tools. Model selection, instructions, available actions, and failure handling are configured for the implementation.

Where does the platform run?

Wizergos runs in a customer-hosted, on-premise environment. Our team can discuss your infrastructure and integration requirements, including any external AI services you choose to use.

Can we deliver both web and mobile experiences?

You can configure device layouts and publish supported web, mobile, and conversational application experiences. Packaging and distribution requirements should be agreed for your chosen delivery channels.

Does low code mean we will never need developers?

Many screens, data structures, and rules can be configured visually. Complex integrations, custom behavior, deployment, and operational setup may still need technical expertise.

How do we test and release an application?

Use application validation and transformation testing, generate supported test packages for external execution, and promote application versions through export, import, and synchronization. Session details and operational monitoring help with ongoing review.
